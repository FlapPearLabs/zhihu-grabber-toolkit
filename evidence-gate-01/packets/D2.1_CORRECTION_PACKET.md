## 1. Defect being corrected (external-audit confirmed)

### CRITICAL_ASPECT_CHAIN = QUESTION_PROVENANCE_LOST

The D2 pilot evaluator (`benchmark/harness/lib/value-units.mjs` in the frozen
2026-08-27 audit pack) assigned each `critical_aspect` value unit:

```js
question_id: primary.length ? qidOf(primary[0]) : null
```

and each `required_contradiction_side` unit:

```js
question_id: qidOf(sids[0])
```

Consequences (verified against real gold):

1. **Order dependence** — question membership came from the FIRST element of
   `primary_sources[]` / `stances[..][]`; shuffling the gold array can change
   which question the unit belongs to (and therefore change every
   per-question metric).
2. **Cross-question collapse** — a genuinely cross-question aspect was silently
   attributed to ONE question. Real example in `case-cross-lowcode`:
   - `case-cross-lowcode:asp-concept` spans questions
     `[462973596, 477427067, 485463474, 487214224]` but was assigned `477427067`;
   - `asp-pitfalls` spans `[485463474, 487214224]` but was assigned `485463474`;
   - `case-cross-lowcode:asp-criteria` spans `[462973596, 477427067]` but was
     assigned `477427067`.
3. **Metric distortion** — per-question denominators/majority and
   minority-question recall were computed on the collapsed attribution.

## 2. Corrected scope model (this experiment: `lib/value-units.mjs`)

Every value unit now carries:

```text
scope        = 'QUESTION' | 'CROSS_QUESTION' | 'CASE'
question_ids = canonical sorted set of question ids mechanically derived from
               ALL of the unit's own supporting sources
```

Rules:

- **QUESTION-scoped** — one supporting-question (e.g. single-source must-see /
  unique-claim; single-question aspects): `question_ids = [qid]`.
- **CROSS_QUESTION-scoped** — aspect / contradiction-stance / claim whose
  supporting sources span ≥2 questions: full `question_ids = [...]` preserved;
  never collapsed onto one question.
- **CASE-scoped** — `expert_source_group` / `evidence_source_group` have no
  legal question ownership: `question_ids = []`; they are excluded from every
  per-question denominator and from `minority_question_recall` (denominator
  rule per task §A1).
- All supporting lists and question sets are canonically sorted in the derived
  artifact, so the derived value-units JSON (and dataset-version hash) is
  byte-stable under any gold array order.

### Per-question credit semantics (`lib/metrics.mjs`, D2.1)

A unit is counted in question `q`'s denominator when `q ∈ question_ids`, and is
**covered FOR `q` only when a selected supporting source FROM `q` exists**
(`unitsCoveredForQuestion`). Cross-question units are never credited to a
question via another question's source.

## 4. Why no STOP was declared

Phase A hard-stop conditions were evaluated:

- **Gold must change to fix evaluator?** NO — gold files untouched (byte-identical
  to pilot D2 pack; validator V2 asserts sha256 equality for all 8 pilot cases).
- **Case semantics ambiguous?** NO — every source id is `qid:answerId`
  (mechanical provenance); multi-question membership is a set over supporting
  sources. Deterministic and unambiguous.
- **Provenance not mechanically recoverable?** NO — see (2).

## 7. Previous reporting error — formally corrected

The D2 pack claimed (11_OPEN_QUESTIONS §1): *“case 级 aspect … 因此不进入
per-question coverage 的分子分母。但只有 aspect_recall 移动了；
per-question / minority / diversity 未受影响。”*

**That claim is FALSE under the corrected evaluator.** See
`packets/D2_TO_D2.1_METRIC_DIFF.md`: `per_question_coverage_preservation`
changed in **12/12** cross-lowcode runs and `minority_question_recall_macro`
in **9/12**; `aspect_recall` did NOT change (0 occurrences). The reason the
pilot saw no movement was precisely the bug: collapsed units were invisible in
the questions they actually belonged to.
