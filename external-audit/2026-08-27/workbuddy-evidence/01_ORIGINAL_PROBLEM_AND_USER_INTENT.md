# ZHCLIPRO_EXTERNAL_AUDIT_PACK — 01 ORIGINAL PROBLEM AND USER INTENT

> 目的：让外部 Reviewer 在不接触任何历史对话的前提下，理解这个产品方向的**原始问题**与**用户意图**。
> 所有用户表述均为摘录（见 `selected_conversation_excerpts/`），本文件不做加工与拔高。

---

## 1. 原始问题（从用户视角）

用户长期在知乎做**技术研究与选型调研**，遇到的核心痛点：

1. **答案质量差异巨大**：高赞回答不等于高质量回答；低赞回答可能包含关键专业信息（长尾价值）。
2. **研究问题跨多题**：一个 research question（如"低代码平台怎么选"）对应知乎上多个问题（选型、对比、坑、案例……），单题抓取会漏掉其他题目的证据。
3. **内容过载**：千赞大问题下回答成百上千条，无法全部阅读；需要自动选出"值得读的子集"。
4. **信息完整性要求**：用于研究/决策的语料需要覆盖——权威观点、反方观点、证据（链接/代码）、新鲜内容、专业作者，而不是只看人气。

用户的原话摘录（`selected_conversation_excerpts/01_original_problem.md`）表达了"回答质量排序"的初始直觉，随后演变为"研究覆盖"（详见 05）。

## 2. 用户意图的核心要素（跨多轮确认）

| 意图 | 表述来源 | 状态 |

| 结论要经过**独立审查**（ChatGPT 逐轮 gate；最终 Claude 外部审查） | 每轮任务书 | 稳定 |
| **不急于实现**：在 Benchmark 证明方法价值之前，不写 Spec、不建产品 | SPEC_PREPARATION_GATE = NOT_READY | 当前状态 |

## 3. 用户未要求的（明确边界）

- 未要求"全站完整研究"（Level 1 07 明确禁止该表述）。
- 未要求规模化抓取（pilot 原则：small high-quality，NOT mass scraping）。
- 未要求任何违反知乎条款的爬虫行为；安全边界见 04。
- 未要求"为了进度强行 PASS"（pilot 失败条件明确：不得包装失败为成功）。

---

## 4. 用户方法论的固定特征（影响一切后续决策）

1. **Gate 制**：每阶段由独立 reviewer（ChatGPT）审查后才放行下一阶段。
2. **失败必须记录**：禁止压缩/隐藏失败实验；保留全部 evidence 与 failed experiments。
3. **证据驱动**：每项声明附文件路径 / SHA / 可核验 artifact；禁止 rebuild / summarize / guess。
4. **审计与修复分离**：发现缺陷先报告，修复走独立授权轮。
5. **单方向记忆沉淀**：workspace memory → 文档 → review → 仓库，禁止反向同步。

这些特征解释了 08 中为什么会有如此多轮 CHANGES_REQUESTED 与修正——**这是流程设计的一部分，不是失控**。
