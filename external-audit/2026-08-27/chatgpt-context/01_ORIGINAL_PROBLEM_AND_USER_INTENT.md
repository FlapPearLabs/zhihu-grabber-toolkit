## Starting point

v0.3 was a trusted **single-question** Research Orchestration product: natural-language request → search candidate Zhihu questions → choose one → capture/verify/analyze that question. It explicitly did **not** claim cross-question aggregation. See `primary_evidence/v0_3/`.

## User expansion request

The user then asked for six concrete expansions: QR/session login, broad official developer-platform compatibility, cross-question research, Pin/想法, active author monitoring, and full currently-accessible history aggregation. Exact wording is in `conversation_evidence/2026-08-25_PRODUCT_NEXT_STEP_USER_VERBATIM.md`.

## Earlier quality intuition

Before the Universal CLI discussion, the user had already articulated quality signals: evidence-bearing answers (images, papers/web references, code/formulas), topic-relevant credentials, while explicitly refusing to exclude low-follower/unverified authors. Exact recovered wording is in `conversation_evidence/2026-08-07_QUALITY_SIGNALS_USER_VERBATIM.md`.

## Important caveat

These user statements describe desired value and intuitions. They do not prove that lanes, MMR, expert quotas, or any specific selector architecture are correct.
