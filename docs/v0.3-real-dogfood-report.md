## 0. CORRECTION — T11-R1 #27（RCA 纠正，2026-08-24）

原报告 §5 将生产失败归因于「长 canonical sourceId 截断回显」并建议「改为短不透明 token」。
**该 RCA 不成立，已由仓库真相 + 生产路径复现纠正（T11-R1 #27）：**

1. **SHORT_TOKEN_IS_ALREADY_IMPLEMENTED**：生产 L1（`lmstudio-map-executor.mjs runChunkMap`：
   `token = String(index+1)` → `buildProjection({sourceId: token})`）与 hierarchy
   （`scripts/map.mjs synthesizeLevel`：`token = String(gi+1)`）**均已使用短 token**；
   控制器要求回显匹配并映射回 canonical sourceId。
2. **LONG-ID 截断实验 ≠ 生产失败**：原 §5.1「5/5 截断复现」是**自定义诊断实验**
   （直接用长 canonical sourceId 作投影 token 调 LM Studio），**不经生产路径**；它只证明
   `LONG_ID_ECHO_IS_UNRELIABLE_IF_EXPOSED`，不证明生产暴露长 ID。
3. **真实生产失败（生产路径复现，T11-R1 #27 记录）**：
   - 类 1 — **概率性输出身份污染（SHORT_TOKEN_ECHO_FAILURE）**：模型把投影头格式或 meta 行抄进
     sourceId 字段——26421707/153737013（token "3"）返回 `"sourceId":"SOURCE 3"`；
     26546908/33355804（token "1"）返回 `"sourceId":"无名（赞同 951）"`；
     19668080/16713310 与 23933514/65631563 在再复现时**通过**（概率性）。
   - 类 2 — **概率性数字 confidence 越界** [0,1]（同一输入有时合法、有时越界）。
4. **修复（#27，产品方批准的最小方案）**：模型输出**不再包含 sourceId**（身份由 controller
   确定性归属）；confidence 改为**枚举 high/medium/low**（strict json_schema 实测 6/6 约束可靠）；
   投影 meta 移除 voteupCount（保留 corpus 元数据）。修复结果见 §5.4 与 §9。
5. 措辞纠正：原 §1「规模越大**越必然阻断**（实证而非外推）」改为——观测到的 per-source 失败行为使
   较大语料**累积失败风险上升**；这**不数学证明**每个足够大的语料必然失败。以证据适当的措辞表述。

T11 对三个真实知乎语料规模带（~50 / ~200 / ~500）执行了端到端 dogfood：

**关键结论（先行版）：**

1. **抓取与验收链路稳定**：4 个真实语料（47/79/183/318 条）全部 `valid=true` 验收通过；
   countMismatch 保持 DIAGNOSTIC_ONLY（19668080: 183/185、23933514: 318/324）。

   Qwen3 1.7B 的**概率性输出身份污染**（把 `[SOURCE N]` 头格式或 meta 行抄进 sourceId 字段）与
   **概率性数字 confidence 越界**，被 T6 控制器确定性拒绝（fail-closed，正确）。
3. **影响（实测）**：全量 digest 要求 100% source coverage（不可跳过任何来源），任一来源 map fail-closed
   即阻断该语料的 digest。47 条语料 digest 完成（0 失败）；79 条 78/79 成功、1 源失败 → 阻断；
   183 条（8 chunks 仅 2 map）、318 条（17 chunks 仅 2 map）均被阻断。观测到的 per-source 失败使较大
   语料**累积失败风险上升**，但不数学证明每个足够大的语料必然失败（证据适当措辞）。
4. **hierarchical digest 实现本身工作正常**：47 条语料 flat+显式 hierarchy 双路径均产出
   `mode="digest"` final.json，verify 全 gate 通过；47 条规模（2 chunks）未触发聚合（ADAPTIVE 设计使然，
   默认 profile 参数 16/32000 下 <16 L1 节点不建层）。
5. **Issue #3 判定：保持 OPEN**。大型语料工作流的可用性/成本问题未被证明解决——模型质量阻断
   200+ 规模的全量 digest，hierarchy 的降本收益无法在真实 200/500 规模上完成对比验证。

## 5. 模型质量发现（MODEL_QUALITY_LIMITATION，非 PRODUCT_CODE_DEFECT；RCA 已由 #27 纠正）

> 本节为 T11-R1 #27 纠正后的最终版本。原「长 canonical sourceId 截断」归因不成立（生产已用短 token，
> 见 §0）；下列为生产路径复现的真实失败模式。

### 5.1 事实 A — 生产失败：概率性输出身份污染（SHORT_TOKEN_ECHO_FAILURE）

**生产路径已用短 token**（`token = String(index+1)`）；模型仍需在输出中回显 sourceId 字段，
而 Qwen3 1.7B **概率性**地把投影头格式或 meta 行抄进该字段：

- 26421707/answer-153737013（EXPECTED_TOKEN="3"）：模型返回 `"sourceId":"SOURCE 3"`（把 `[SOURCE 3]`
  头文本抄进值）。
- 26546908/answer-33355804（EXPECTED_TOKEN="1"）：模型返回 `"sourceId":"无名（赞同 951）"`（把 meta
  `来源: <author>（赞同 <voteupCount>）` 抄进值——voteupCount 原在模型可见 meta 中）。
- 19668080/answer-16713310 与 23933514/answer-65631563：生产路径再复现**通过**（概率性，非确定性）。
- T6 控制器判定（两种污染均）：`capability_isolation_unavailable: structured output references an
  unknown or mismatched source ID` → chunk 不写 map，fail-closed（正确，零降级）。

### 5.2 事实 B — 诊断实验：长 canonical ID 直接作为投影 token 时的截断

- 触发：自定义诊断调用 `buildProjection({sourceId: 'question-26421707-answer-153737013', ...})`
  （长 canonical ID 作投影 token），**不经生产 runChunkMap 路径**。
- 结果：模型返回 `"sourceId":"question-26421707"`（截断，5/5 稳定）→ 仅证明
  `LONG_ID_ECHO_IS_UNRELIABLE_IF_EXPOSED`。
- **不构成生产失败证据**：生产从未把长 ID 暴露给模型。原 §5.1 的「截断 5/5」即此实验，已纠正。

### 5.3 事实 C — 概率性数字 confidence 越界

- 触发：模型对部分输入输出 `confidence` 数字越界 [0,1]（如 meta 数字误回显；T8 live smoke 同类实证）。
- 稳定性：同一输入（19668080/16713310）再复现时输出 `confidence: 1.0` **合法通过** → 概率性。
- T6 控制器判定：`capability_isolation_unavailable: structured output confidence is invalid` → fail-closed（正确）。

### 5.4 修复与验证（#27，已实施）

- **模型输出不再含 sourceId**：schema 移除 sourceId 字段（`additionalProperties:false`），controller
  从 trusted 请求状态确定性归属 sourceId/sourceCoverage/claim.evidenceSourceIds；模型输出携带任何
  sourceId 字段 → fail-closed。
- **confidence 枚举化**：wire 改为 `high/medium/low`；真实 runtime strict json_schema 约束实测
  6/6 可靠（P4 probe，2026-08-24）；数字 confidence 一律拒绝。
- **投影 meta 最小化**：移除 voteupCount（保留 corpus 元数据）；author 保留为安全非敏感形式。
- **P7 requalification**：新协议 adversarial battery 实测 `valid:true`（引用类项 controller 拒绝；
  corrupt_evidence 项正确 fail-closed）。
- 全量测试：corpus 173/0、agent-pipeline 6/0、zhihu 507/0（#27 提交后）。

**模式 B — confidence 越界（meta 数字误回显）**

- 触发输入：`question-19668080-answer-16713310`（803 chars / voteup 51，普通规模）。
- 模型输出 `confidence` 越界 [0,1]（T8 live smoke 已实证同类：模型把「赞同 N」meta 行数字抄进 confidence）。
- T6 控制器判定：`capability_isolation_unavailable: structured output confidence is invalid` → fail-closed。
- 稳定性：2/2 失败（有界重试）。

### 5.5 对 #3 的意义

Issue #3 的「大型语料全量合成成本问题」在**模型质量层面**遇到真实天花板：即便 hierarchy 实现了
`claims -98.7%（synthetic 538 源）`的降本结构，Qwen3 1.7B 的 per-source 映射失败率也使 200+ 规模
无法可靠产出 full-coverage digest。**#3 保持 OPEN**，并记录本证据。
