## 一、系统状态机设计 (System State Machine)

整个产品体验由一个严格的 4 状态有限状态机（FSM）驱动，杜绝传统 Chat 界面的不可预测性与混乱交谈流：

```mermaid
stateDiagram-v2
    [*] --> State_0_Idle: 初始访问 / 首页
    State_0_Idle --> State_1_Assembly: 用户输入议题 + 回车 / 点击运行
    State_0_Idle --> State_3_Result: 点击置顶精选研报 (0秒秒开, Skip State 1)
    
    State_1_Assembly --> State_2_Synthesizing: 语料抽取完毕，进入矛盾识别与证据比对
    State_2_Synthesizing --> State_3_Result: 报告装配完成，平滑展开为完整研报
    
    State_3_Result --> State_4_Evidence_Open: 点击任何 Claim 的引用标 [1] / 关联问题
    State_4_Evidence_Open --> State_3_Result: 关闭侧边抽屉 / Esc
    State_3_Result --> State_0_Idle: 点击顶栏返回 / 新建研究
```

### 状态细则：
* **State 0: Idle (沉浸探测台)**：主输入框获得焦点，提供置顶精选研报的零延迟入口与核心价值对比。
* **State 1: Assembly (研报骨架动态装配)**：双轨推进。左轨逐步点亮 Aspect 和关联问题，右轨实时捕获知乎高价值回答与答主脉冲。
* **State 2: Synthesizing (共识与分歧提取)**：进度进入 80%+，出现冲突卡片的预装配动效，消除长时间白屏或卡顿焦虑。
* **State 3: Result Dossier (研报阅读台)**：四层递进式结构展开，默认停留在第 1、2 层。
* **State 4: Evidence Inspector (证据检视态)**：侧边 420px 抽屉滑出，主阅读区轻微半透明遮罩，锁定当前证据链。
