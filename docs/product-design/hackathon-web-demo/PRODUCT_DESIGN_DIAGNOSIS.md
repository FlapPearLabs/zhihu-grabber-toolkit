# PRODUCT DESIGN DIAGNOSIS
## Cross-Question Deep Research for Zhihu (Hackathon Edition)
> **Author**: Senior AI Product Designer · Interaction Designer · Frontend Design Director  
> **Phase**: Round 1 — Product Strategy & UX Diagnosis (Design First. Zero Implementation.)

---

## 1. 这个产品真正卖的是什么？

### 一句话定义：
> **它卖的不是“信息检索的答案”，而是“对知乎公共认知生态的跨议题调查与共识/分歧制图”（Cross-Topic Cognitive Cartography & Evidence Audit）。**

### 深度解构：
市面上的 AI 搜索（Perplexity、秘塔、Kimi）本质都在解决 **“收敛”** 问题——把散落的事实压缩成一段标准答案。但这彻底误读了知乎的生态价值：
* **知乎从来不是维基百科**。知乎的核心资产不是“客观中立的百科事实”，而是**“带着个人真实踩坑经验、行业上下文与利益立场的专业主观性（Professional Subjectivity with Skin in the Game）”**。
* 单看一个知乎回答是**个人偏见**；单看一个知乎问题是**盲人摸象**（很多知乎提问本身就带有立场预设或情绪诱导）；
* 真正的认知价值，散落在 10 个不同角度的提问、300 个不同背景答主跨越数年的实践反思与观点交锋中。

因此，这个产品卖的是：**把散落在知乎不同角落的真实经验、专业判断和观点冲突，重新提炼为一份可审计、有证据链、能看清各方博弈战场的认知全景。**

#### 对现有候选产品文案的批判与重构：
| 候选文案 | 致命缺陷 | 改造建议 |
| :--- | :--- | :--- |
| **“一个问题，看完整个知乎怎么回答”** | ❌ **虚假承诺**。听起来像暴力爬虫汇总或粗暴的摘要机器，且“看完整个知乎”在技术可信度上极假，评委一眼挑刺。 | **“一个议题，穿透知乎多维讨论”** |
| **“不只搜索一个知乎问题，而是研究整个知乎里的相关讨论”** | ⚠️ **工科直男式自白**。在解释技术动作（搜 vs 研），没有传递给用户的终极智识价值。 | **“不向知乎要单一结论，向整个知乎要共识与分歧”** |
| **“把散落在知乎里的真实讨论，变成一份可以验证的研究”** | 接近正确，但“可以验证”稍微有些学院气，缺乏传播穿透力。 | **“跨问题透视知乎真实经验，绘制有证据的认知全景”** |

## 2. 用户最大的 Aha Moment 是什么？

绝对**不是**看到最终生成了一篇辞藻华丽的 AI 综合长文——现在的用户和评委已经被 ChatGPT 的“大词废话长文”看吐了。

真正的 Aha Moment 发生在**两次心理震颤（Shockpoints）**：

### ① 瞬间 A：跨议题穿透的“意料之外，情理之中”（Cross-Topic Discovery）
* **场景**：用户输入 `AI 编程工具真的会取代程序员吗？`
* **普通 AI 搜索的表现**：去搜这个问题本身，然后总结：“有人认为会，有人认为不会……”。
* **本产品的 Aha 瞬间**：
  界面解析议题切面时，用户赫然看到系统把**《作为研发总监，你现在招人的标准变了吗？》**、**《初级外包岗位的真实流失率》**以及**《某金融系统因为 AI 生成代码导致的重大故障复盘》**这三个完全没有包含“取代程序员”字眼、却直击问题命脉的知乎问题并列拉入了研究！
* **心理认知**：**“它不是在做关键词匹配，它真的像一个资深调查记者一样在跨行业挖掘深层关联！”**

### ② 瞬间 B：观点对撞展开时，直达原汁原味知乎回答的“证据锚定”（Evidence Grounding）
* **场景**：报告中赫然出现一个加粗的冲突卡片：
  * **正方**：“大厂核心架构师基于某业务线代码生成率达到 42% 的实测，断言初级代码工必然被淘汰”；
  * **反方**：“资深合规与运维专家指出在金融与安全边界上，AI 造成的隐蔽 Bug 使排查成本增加了 3 倍”。
* 用户鼠标点击这个冲突，侧边平滑滑出**知乎原文的高亮引注、答主认证身份、赞同数以及时间戳（2023 vs 2025 的认知演进）**。
* **心理认知**：**“这不是 AI 编造的幻觉，这是知乎上神仙打架被提炼出来的真相，而且证据就在我眼前。”**

**原则：克制、极速、无须解释。首屏只允许 3 个核心视界单元。**

```
│  │ 🔍 输入一个你想在知乎穷尽调研的复杂议题...       │  │
│  └──────────────────────────────────────────────────┘  │
│         [ 开始深度研究 (Enter) ]                       │

```

### 必留的核心要素：
1. **Research Instrument 气质的 Hero 输入框**：
   * 不要像 ChatGPT 那样悬浮在底部的聊天条，它必须是整个页面的**视觉重心与仪态中心**。
   * 输入框内置优雅的 Scope 说明或微标签：`支持输入复杂论题 / 行业分歧 / 职场真相`。
2. **“0 延迟”的置顶金牌研报（The Featured Living Dossier）**：
   * **Hackathon 评委没有耐心等你跑 40 秒**。如果首屏只有空白输入框，评委可能随便敲几个字嫌慢就关了。
   * 必须在输入框下方直接提供**1 个深度极其惊艳的完整真实研报卡片**，点击利用平滑过渡（Shared Element Transition）**零等待**直接切入 Result Page！让评委第 3 秒就看到最终高潮。
3. **“传统搜索 vs 跨问题研究”的 5 秒微交互对比条**：
   * 用极度精炼的图形动效对比：`1 Question -> 3 Answers -> Summary` VS `1 Topic -> 4 Aspect Clusters -> 23 Questions -> 396 Corpus -> Consensus & Contradictions`。

### 必须坚决砍掉的内容：
* ❌ 砍掉长篇大论的“产品特性介绍卡片（Feature 1, Feature 2, Feature 3）”——AI 产品写这个就是废话。
* ❌ 砍掉大段工程架构介绍。
* ❌ 砍掉假大空的 Hero 背景光晕粒子动画。

## 4. Research Progress 最应该怎样表现？

### 锋利评判 4 个候选方向：

| 方向 | 优势 | 致命缺陷 | 结论 |
| :--- | :--- | :--- | :--- |
| **A. Research Graph (力导向知识图谱)** | 动态视觉强，有“AI 在思考”的即视感。 | **纯粹的炫技灾难**。节点晃动重叠，文字读不清，连线含义不明；在移动端直接崩溃；评委已经对“AI 粒子大脑球”极度审美疲劳。 | **坚决否定作为主视图** |
| **B. Research Timeline (线性步骤列表)** | 结构清晰，容易实现。 | **严重退化成“终端日志 / CLI”**。把高维度的“跨议题并行探索”降维成一条单线程排队流水账，毫无空间感。 | **否定作为核心呈现** |
| **C. Source Landscape (群岛/集群)** | 空间感强，突出“跨问题”体量。 | 静态感太强，缺乏阶段推演的逻辑咬合；且群岛若无文本支撑，只是彩色的色块。 | **可作为局部隐喻，不可独立承载** |
| **D. Hybrid (混合方案)** | 试图兼顾。 | 容易做成信息过载的垃圾堆（上边进度条、中间蜘蛛网、右边跳数字）。 | **需重新定义逻辑，不可盲目拼接** |

### 推荐方案：【The Blueprint Assembly / 研报骨架动态装配】

放弃“看一个 Loading Spinner”或“看节点连线乱飞”，转而采用**“调查研报的骨架现场装配过程”**。

```
┌────────────────────────────────────────────────────────────────────────┐
│  RESEARCH IN PROGRESS                                                  │
│  议题：AI 编程工具真的会取代程序员吗？                      [ 396 语料 / 23 问题 ] │
├──────────────────────────────────┬─────────────────────────────────────┤
│  左侧：研报蓝图生长区 (The Blueprint)│ 右侧：捕获雷达流 (The Radar Stream)  │
│                                  │                                     │
│  [✓] 议题切面解构完成 (4 个维度)   │ ⚡️ 正在穿透知乎问题:                  │
│      ├── 效能实测与工程落地       │   《Devin 发布后，程序员还有未来吗？》│
│      ├── 招聘市场与岗位流失       │   ↳ 发现高赞回答 12 条...           │
│      ├── 软件责任归属与伦理       │                                     │
│      └── 底层逻辑与理论上限       │ ⚡️ 捕获冲突观点:                     │
│                                  │   “生成率42%” vs “隐蔽Bug成本高3倍” │
│  [◐] 正在跨问题比对观点 (184/396)  │                                     │
│      ┌──────────────────────┐    │ ⚡️ 提取关键答主身份:                 │
│      │ 发现关键冲突点 #2:   │    │   知乎资深架构师 / 某大厂效能负责人...│
│      │ “效能提升是否导致裁员”│    │                                     │
│      └──────────────────────┘    │ (平滑向上淡出滚动，速度克制且有节奏) │
│                                  │                                     │
│  [ ] 正在合成证据链与置信度审计    │                                     │
└──────────────────────────────────┴─────────────────────────────────────┘
```

#### 为什么这是最优交互？
1. **利用了 Emil Kowalski 的“知觉速度（Perceived Performance）”哲学**：用户不是在被动等待，而是在提前阅读“即将呈现的报告目录与核心剧透”。
2. **解释了“系统在干什么”**：左边是结构化认知（Macro），右边是真实知乎语料的实时捕获脉冲（Micro）。一虚一实，彻底坐实“系统真的在知乎里跨问题阅读”。

## 5. Result Page 应该是什么阅读结构？

**核心禁忌**：坚决不能做成充满 8 个 Donut Chart 和一堆彩色百分比的 BI 仪表盘！**研究结果首先是让人读的（Editorial），其次才是让人验的（Auditable）。**

### 黄金四层递进结构（Progressive Disclosure Flow）：

```
┌────────────────────────────────────────────────────────────┐
│ SECTION 1: 核心研判摘要 (The Executive Bottom Line)         │
│ • 一句话定性结论 (Hero Conclusion)                         │
│ • 3 个关键发现锚点 (带标签：【结构性共识】【核心分歧】【适用边界】)│
│ • 研究诚实边界小字 (覆盖本次精选 396 篇语料 100%，非知乎全量) │
├────────────────────────────────────────────────────────────┤
│ SECTION 2: 观点博弈战场 (The Battleground: Claims & Tensions)│
│ ┌────────────────────────┐  ┌───────────────────────────┐ │
│ │ 🟢 压倒性共识 (Consensus)│  │ ⚔️ 关键冲突 (Contradictions)│ │
│ │ 85% 答主一致确认的事实  │  │ 正反方针锋相对两栏对照    │ │
│ │ • 样板代码生成率提升超40%│  │ [观点A：初级岗归零]       │ │
│ │   [证据链: 4个问题/18答主]│  │     vs                     │ │
│ │                        │  │ [观点B：架构理解门槛暴增] │ │
│ └────────────────────────┘  └───────────────────────────┘ │
├────────────────────────────────────────────────────────────┤
│ SECTION 3: 跨议题全景折叠卷宗 (The Discussion Landscape)    │
│ 用户在此看到研究真正横跨了哪些知乎空间：                   │
│ 📁 维度 1: 真实生产力与效能踩坑 (归纳自 8 个知乎问题) [展开] │
│ 📁 维度 2: 劳动力市场与招聘冰霜期 (归纳自 6 个知乎问题) [展开] │

│ SECTION 4: 证据下钻抽屉 (Evidence Inspector)               │
│ (页面常驻侧边，点击任何 Claim 上的 [引用标] 平滑滑出)      │

│ • 答主信息 (赞同数、认证头衔、回答年份)                      │

└────────────────────────────────────────────────────────────┘
```

## 6. 哪些技术能力应该显性？

必须通过精致的 UI 语汇，让评委清楚感知到系统的硬核护城河：

1. **议题拓扑关联度（Aspect-to-Question Mapping）**：
   * 明确告诉用户：为了回答这个问题，系统自主构建了哪几个切面，分别找到了知乎上哪些具体问题。
2. **观点冲突与张力（Contradiction Extraction）**：
   * 这是区分垃圾摘要和深度研究的核心标识。必须显性列出“冲突双方的论据支撑点”。
3. **证据血统（Evidence Lineage）**：
   * 每一个核心推论都能向上追溯到 Claim，向下追溯到特定知乎答主的段落。
4. **知乎语境元数据（Contextual Metadata）**：
   * **回答时间戳（Temporal Context）**：AI 领域 2023 年和 2025 年的回答结论可能完全相反，把时间作为权重显性标注出来是巨大加分项；
   * **答主行业背景/认证**：知乎特有的“真实身份权重”。
5. **诚实边界声明（The Transparency Badge）**：
   * 显性展示：`Analyzed Corpus: 396 / 396 (100% Analysis Coverage)`；
   * 鼠标悬浮提示：`“本系统完整分析了选入研究池的所有语料，但不代表囊括了知乎全站该议题下的所有讨论。”`——**这种技术诚信在评委眼里比吹嘘“全网穷尽”高级 10 倍。**

## 7. 哪些工程细节必须隐藏？

必须以残酷的审美砍掉以下“极客自嗨/爹味技术词汇”，普通用户和产品评委看见这些只会觉得是未经雕琢的 Demo：

* ❌ **向量与计算底层**：`Embedding`, `Cosine Similarity`, `Vector Distance`, `Dense Retrieval`, `Rerank Score`。（用户不需要知道余弦相似度是多少，他们只需要知道“为什么这个问题与本题相关”）。
* ❌ **模型与供应商标签**：`DeepSeek-R1`, `GPT-4o`, `Token Count`, `Temperature: 0.7`。（加上这些立刻沦为 API 套壳感）。
* ❌ **工程运行状态字眼**：`Checkpoint`, `Canonical Runner`, `Worker Pool`, `LangChain / LlamaIndex Node`, `Batch Size`。
* ❌ **无意义的置信度百分比**：比如显示 `Confidence: 94.3%`（这种伪精确在专业评委眼里就是胡扯）。转而使用定性标签：`【强共识】`、`【显著分歧】`、`【孤证待核】`。

## 8. Visual Direction（3 个高度差异化的视觉方向）

---

### Direction A — 【The Editorial Investigation / 深度调查卷宗】
* **核心 Metaphor**：顶级深度调查报道（类似《大西洋月刊》或《ProPublica》的研究特刊）。
* **Layout**：典雅的单列主阅读流（Max-width 720px），搭配右侧自适应粘性（Sticky）证据视窗。页边空白充裕，排版呼吸感极佳。
* **Typography**：
  * 中文标题：高质量衬线体（如思源宋体 / 方正榜书），正文采用排版极为舒适的人文无衬线（苹方 / 思源黑体，Line-height 1.75）；
  * 英文/数字：优雅的人文西文字体（Newsreader 或 Playfair Display），搭配少量等宽标尺。
* **Visual System**：
  * 底色：暖米白 / 象牙纸质底（Warm Ivory `#F9F8F6`，夜间模式为墨水深灰 `#141517`）；
  * 墨色：纯黑与炭黑阶梯（`#111111`, `#333333`, `#666666`）；
  * 强调色：克制的**知乎智性蓝**（Deep Zhihu Cobalt `#0055FF`），冲突点使用高饱和赤红（Crimson `#D9383A`），共识点使用鼠尾草绿（Sage `#2E7D32`）。
* **Motion Language (基于 Emil 规范)**：
  * 极度克制。以 `opacity` 与微位移（`translateY: 6px`）为主，曲线采用强 ease-out（`cubic-bezier(0.23, 1, 0.32, 1)`），时间 `180ms - 220ms`。
  * 引用抽屉展开时带有轻微模糊层遮罩（`filter: blur(2px)` 伴随淡入），绝无弹跳。
* **Research Visualization**：纸张折叠式手风琴（Dossier Accordion）+ 边注高亮证据卡片。
* **Why it fits**：彻底消除 AI 塑料感，赋予知乎内容以严肃智识的尊严，非常适合长文阅读与观点细嚼。
* **Biggest Risk**：对部分喜欢看酷炫图形的视觉系评委来说，可能初看显得过于“安静”，需要依靠精致的微交互拉开质感。

---

### Direction B — 【Knowledge Cartography / 动态认知制图】
* **核心 Metaphor**：认知航海与星系制图（Cognitive Atlas）。把知乎的问题海洋视作一个个群岛与航道。
* **Layout**：沉浸式双联画卷（Split Canvas）。左侧 40% 为动态缩放的**“议题切面拓扑岛屿（Aspect Islands）”**，右侧 60% 为随地图交互联动高亮的报告主体。
* **Typography**：
  * 现代国际主义无衬线（Inter / Geist / SF Pro），搭配精密等宽数字字体（Geist Mono），字重对比强烈（Display Heavy + Body Regular）。
* **Visual System**：
  * 底色：深邃制图台黑夜（Obsidian `#0A0C10` 到 `#12161F` 的极微渐变）；
  * 材质：半透明磨砂玻璃层（微克制的 Glassmorphism，`1px border` 带 `rgba(255,255,255,0.08)`）；
  * 强调色：**知乎电光蓝（Electric Blue `#0084FF`）**作为主能量线，共识桥梁采用翡翠青（Emerald `#00E5A3`），争议断层采用荧光琥珀（Amber `#FF9F1C`）。
* **Motion Language**：
  * 物理弹簧动效（Apple 规范：`{ type: "spring", duration: 0.45, bounce: 0.15 }`）。
  * 鼠标悬停在右侧 Claim 时，左侧地图对应的几个知乎问题节点同时呼吸式放大并连线汇聚，视觉联动极其丝滑。
* **Research Visualization**：节点群岛（Clusters）+ 动态引力光斑。
* **Why it fits**：**舞台 Demo 效果极其炸裂**，5 秒内就能抓住任何评委的眼球，完美直观地具象化了“跨问题”这个抽象概念。
* **Biggest Risk**：**移动端灾难**（必须为手机端做彻底的降级为纯列表）；若处理不当容易让评委只看地图而忽略了真正有价值的研究内容。

### Direction C — 【The Precision Instrument / 认知真理终端】
* **核心 Metaphor**：彭博终端（Bloomberg Terminal）与 Linear / Raycast 现代极客美学的合体。将知乎视作“非结构化人类智慧的交易与结算所”。
* **Layout**：现代 Bento Grid（便当盒网格布局），信息密度极高但井井有条，全模块化卡片组合，强键盘快捷键驱动（全站支持 Cmd+K / J-K 翻动证据）。
* **Typography**：
  * 工业级机械感。极度干净的无衬线，搭配大量等宽数字标尺（JetBrains Mono / SF Mono）。
* **Visual System**：
  * 底色：深石墨灰（Graphite Slate `#0F1115`，卡片表面 `#181B22`，边框 `#262B35`）；
  * 状态标识：微发光指示灯（Status Dots：🟢 Validated / 🟡 Divided / ⚪ Insufficient）；
  * 强调色：冷色调知乎蓝（Steel Blue `#2563EB`）配搭高对比纯白文本与哑光灰副文本。
* **Motion Language**：
  * 毫秒级极速响应（`100ms - 140ms`，linear 或 sharp ease-out）。
  * 严格遵从 Emil 规范：**高频交互绝无多余回弹动画**，卡片收放如精密机械卡榫咬合。
* **Research Visualization**：矩阵式切片对比表（Matrix Diff View）+ 实时吞吐数据流。
* **Why it fits**：散发着无与伦比的技术掌控力与极客硬核感。对于知乎 Hackathon 的技术背景评委，这种“无废话、高密度、高操控性”的风格极度受尊重。
* **Biggest Risk**：对非技术背景或重度人文偏好的评委可能会产生“压迫感”，显得略微冰冷。

## 建议与下一步决策

这是我们接下来的关键决策点：

1. **核心产品文案定调**：是否认可将叙事重心从“看完知乎”转为**“跨议题穿透与共识/分歧全景”**？
2. **视觉方向选择**：在 **Direction A（深度调查卷宗）**、**Direction B（动态认知制图）**、**Direction C（认知真理终端）** 中，你更倾向哪一个基调？
   * *设计总监个人推荐*：采用 **Direction A 的阅读尊严与排版骨架**，但在关键的“跨议题 Landscape”模块中，克制地融入 **Direction B 的动态切面联动交互**。这样既能保证 40 秒 Demo 的视觉冲击，又能支撑评委后续的沉浸式细读。
3. **首屏策略**：是否同意采用 **“1 个输入框 + 1 个零秒加载的置顶精选真实研报”** 的首屏防崩塌策略？
